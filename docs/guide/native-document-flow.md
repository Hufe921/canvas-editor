# T15 原生文档流

正文的原生排版现在直接消费目标页、栏和浮动占用区间；不再用首节宽度排完整段，
再平移成品行。字形仍由 HarfBuzz 整形，段落输入与缓存包含逐行宽度及水平偏移。

## 分页与环绕

`DocumentFlow` 以未缩放 CSS 像素维护页码、纸张方向、栏号及纵向游标。
每次落位查询该页实际页边距、页眉页脚占位和对应方向的栏宽。
溢出优先推进栏，显式分页符直接开启下一页及新节，后续页继承节方向。

多个环绕矩形从行盒区间中求差，选择最大的合法连续区间；同宽时按段落方向取起始侧。
完全阻塞或不能容纳首个字形簇时推进到遮挡底部，必要时换栏/页。
`FlowParagraphHost` 用实际字体行盒反复求解逐行约束，重新断行并在最终行界整形，
随后才投影到兼容行。嵌套列表缩进以当前栏宽及首簇宽度为界，列表标记跟随同一落点。
空行光标也使用受约束区间。原生节点保存页/栏 placement。

表格按完整栏窗口流动，先跨过该栏的浮动占用再拆分；不会把整表横移到不足容纳它的缝隙。
非表格对象按自己的宽高落位。连续页的高度包含环绕造成的纵向跳跃。

## 表格窗口与截断

- `TablePaging` 接收同一原生游标，从实际页、栏与已消费高度开始拆分；
  首片段的 Area.top 只预留一次，后续正文从末片段的落点继续。
- 每个片段记录目标页栏、完整行范围及首尾拆行偏移。原生 `sliceTableFragment`
  将同一窗口转换为单元格 clip，跨行单元格保留原 cell scope；子节点坐标仍为单元格局部值。
- 重复表头在片段内独立回放，不扩展逻辑数据范围。每个续页按当页真实可用高度决定
  是否容纳重复表头，避免页眉禁用状态不同而导致拆分失败。
- 最终分页直接采用 flow placement，不再第二次判断换栏与溢出。
  `maxPageNo` 的正文及拆表截断统一到同一入口；表格保留已显示窗口、修复跨度及上下文，
  行列表同步收缩，避免绘制已裁掉的行。没有为每页复制持久化表格。

## 容器与缓存

正文使用 main scope，单元格使用 td scope，单元格排版不会推进正文页栏。
页眉页脚使用 `header:vertical/horizontal`、`footer:vertical/horizontal`，
其单元格 scope 也包含框架方向，避免同一元素区间覆盖另一种纸张宽度的结果。
兼容行在框架内保留独立几何快照；位置及命令接口查询时恢复当前方向的单元格几何。
键盘视觉移动也按当前页方向选择框架缓存。

`Position` 消费 flow 的纵向落点，并按当前页方向获取栏偏移。
RTL 栏首点击保留行首锚点，避免光标落回前一栏的末元素。
T14 的缺字定位仍使用稳定元素标识与表格路径，布局 scope 变体不会改变源身份。

## 验证与后续边界

本次定向检查通过 8 个 Vitest 文件（115 项）和 26 个 Cypress 场景。
类型检查、编辑文件 ESLint、ESM 构建及包消费者检查通过。

定向测试覆盖横竖节切换、显式分页跨过剩余栏、多浮动占用、窄缝、完全遮挡、
跨页/栏表格、重复表头、跨行单元格 clip、Area.top、maxPageNo 重绘稳定性，
以及页眉与页眉表格方向缓存。浏览器另验证 LTR/RTL 跨栏点击及打印。

全量回归按约定暂缓。受页栏/环绕约束的正文暂不复用旧段落增量结果；
脏区间与原生增量迁移由 T18 继续处理。统一交互消费者及旧循环删除分别属于 T17/T20。

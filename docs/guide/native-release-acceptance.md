## T23：性能结果与可比性

T01 原记录没有墙钟性能数据。以下是**同机历史提交复测**，不是当时留存的性能金图。
两版完成的工作不同：旧版存在浏览器文字绘制、对象回退与按文本保留的段落缓存；
当前版显式检测覆盖、生成字形路径、原生 cluster/caret 和对象几何。
新行高度/分页也不同，例如 7,701 元素的多段样本为旧版 10 页、当前 19 页。
因此可比较迁移的实际成本，不能把比值当成视觉等价算法的吞吐量比。

### 冷实例与只绘制

`startup` 从 Draw 构造开始，到 ready 后强制完整同步绘制结束；字体下载、文档规范化与
浏览器模块加载在此计时区间外。`module + startup` 额外包含页面模块就绪的观测时间，
是本地开发服务器的分段总和，不能等同网络冷缓存或用户感知 LCP。
每个 context 是冷 JS/WASM 实例，操作系统及浏览器磁盘缓存没有清空。

### 分阶段归因

包装真实方法记录累计 CPU 墙钟时间，下面为每次编辑阶段均值在三轮中的中位数，单位 ms。
`flow` 包含整形，coverage 包含扫描/resolve；嵌套与中位数不能直接相加为总耗时。
对象测量由含表格/控件/环绕的 flow 样本覆盖，不把 flow 全部冒称为纯对象测量时间。

| 样本/配置     | flow（含整形） | 其中整形 | 分页 | 坐标重建 |  绘制 | 覆盖扫描总计 |
| ------------- | -------------: | -------: | ---: | -------: | ----: | -----------: |
| 多段 / 完整   |         157.15 |    43.00 | 0.03 |   153.10 | 39.94 |        22.76 |
| 多段 / 增量   |         175.54 |     1.29 | 0.01 |   168.65 | 27.21 |        24.46 |
| 超长段 / 完整 |         196.25 |    41.05 | 0.01 |   189.99 | 30.72 |        28.44 |
| 超长段 / 增量 |         533.72 |    46.01 | 0.01 |   222.60 | 43.91 |        30.15 |

已定位的主要成本：

1. `IncrementalParagraphComputer` 的缓存键序列化、布局克隆和 source 重定位都有成本；
   多段正文省下整形，但仍需重建宿主视图、分页和所有交互坐标。
2. 单超长段仍是同一个脏段，无法复用段内未修改行；整段重算后再缓存/克隆，可能更慢。
3. 分栏、图片、列表等复杂结构保守退回完整 HB 流，不能保证增量收益；
   当前开关也会进入若干段落级缓存路径，因此有额外缓存处理成本。
4. 原生 Position/InteractionGeometry 建立真实簇、caret、选区位置；旧坐标成本明显更低。
5. 当前字形轮廓绘制、更多实际页面和覆盖诊断执行旧版未执行的工作。
   未为追求旧版数字而恢复浏览器文字绘制或关闭布局特性。

集中缺字样本完整 HB 的覆盖扫描约 9.10ms/编辑，其中 resolve 约 6.12ms，
诊断更新约 0.75ms。三轮均只有启动时 2 次分类告警，8 次编辑及 5 次重绘无新增告警。
去重状态不按每次文档 revision 无限累积。

## T23：资源与销毁

- 100 段正文，6 批 × 30 次编辑，逐批强制 GC。
- 首轮性能压力样本 JS heap 从 99,437,400 到 99,604,392 字节，约增长 0.16 MiB；
  DOM 固定 419 节点、95 个监听器，没有随编辑次数线性增加。
- 段落缓存达到并保持 256 项；字体实例 2、覆盖缓存 93、轮廓 52 项/204,426 字节，
  宿主布局索引 103；通用旧布局缓存为空。
- 单实例销毁后段落、布局、字体 face/实例、覆盖、轮廓与告警集合全部为零；
  页面 Canvas、诊断 DOM 和该实例注册的 document.fonts 均移除。
- 独立生命周期轮运行 8 次创建/销毁；强制 GC 后 heap 约 11–13 MB 波动，
  最终 DOM 为 18 节点、18 个监听器，与稳定轮相同。部分轮仍可见待释放的 detached DOM，
  随后任务/GC 后恢复，没有逐实例增长。
- 单测另覆盖轮廓 LRU 淘汰、资源缓存 LRU、字体下载订阅释放、失败、超时与缓存失效。

这是有限压力与销毁检查，不能证明所有未来文档没有内存问题。
256 项布局缓存按条目限制，不是整个编辑器 heap 的字节上限；大段落会占用更多内存。
共享 HarfBuzz WASM/模块保留属于运行时复用，不要求销毁一个实例就卸载共享模块。

原始证据：[当前版性能](/validation/t23-native.json)、
[T01 复测](/validation/t23-t01.json)、[独立资源/生命周期](/validation/t23-resources.json)。

## 破坏性变更与迁移交付

1. 原 npm 包替换为 `@herberthe/canvas-editor`，独立版本线从 0.1.0 开始。
2. 只支持根 ESM 与 package.json 子路径；不支持 UMD、require、内部深路径。
3. 移除文字引擎模式与枚举；旧配置报迁移错误。页面固定 Canvas；SVG renderer 请求明确拒绝。
4. 初始化改用 `await Editor.create()` 或 `await editor.ready`；ready 不等待后台基本字体下载。
5. 字体必须以实际字节/URL 注册；默认下载可关闭，缺字保留占位并提示，不用系统浏览器字体偷偷回退。
6. 原生字体度量、段落间距、分页、簇编辑可能与旧浏览器度量不同，迁移需重新验收文档与插件。
7. 性能存在上表所示成本，不承诺旧版速度；复杂结构与单超长段不能作为增量收益宣传。

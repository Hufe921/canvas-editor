# 实验特性

实验特性统一放在 `lab` 配置项下，**逐项默认关闭**。这些特性可能随版本调整或移除；未配置 `lab` 时编辑器行为与历史版本完全一致，且没有任何额外开销。

```typescript
new Editor(container, data, {
  lab: {
    incrementalCompute: true
  }
})
```

## incrementalCompute 行级增量行计算

### 解决什么问题

默认情况下，每次编辑（如打一个字）都会从头重排整个文档：行计算、分页、元素坐标、历史快照都是全量的。文档达到数万至十万级元素时，单次按键耗时会超过一帧的预算（16ms），打字明显卡顿。

开启 `incrementalCompute` 后，行计算改为行级增量：

- 排版时为每一行记录起始状态快照（恢复点）
- 编辑时仅从受影响行断点续算，与某个旧行结构状态收敛（通常 1~3 行）即停
- 收敛点之后的旧行对象原样复用；首个变动页之前的页坐标也直接复用缓存

大文档、长段落场景下单次按键耗时可下降一个数量级；小文档无感。

### 自动退化

以下场景行级增量不参与，自动退回全量计算（行为与未开启时一致）：

- 表格内部编辑、控件内部编辑、页眉页脚编辑
- 文档存在浮动/环绕图片、分栏布局
- 文档存在 `minWidth` 空值控件（生成占位元素期间）
- 发生 `maxPageNo` 截断、布局变更（缩放/边距/纸张/页眉页脚等）

### 注意事项

- 该特性只影响渲染性能，不改变任何排版结果：增量路径与全量路径的计算结果逐字节一致（有差分测试保障）
- 实验性接口，配置项名称与行为可能在未来版本调整

### 二次开发须知

修改文档元素必须走统一入口，行级增量行计算才能正确追踪：

- **增删元素**：`draw.spliceElementList` / `draw.deleteElementList`（自动记录脏区间）
- **原地改字段**：`draw.setElementProperty(elements, { ... })` / `draw.deleteElementProperty(elements, [keys])`（自动标记下次渲染全量计算）

直接对元素结构字段（listId/titleId/rowFlex 等）赋值或 `delete` 会绕过追踪产生陈旧行复用，请务必使用访问器。纯原地修改（无增删）没有脏区间时渲染必然全量，访问器调用是无害的，无需判断场景。
